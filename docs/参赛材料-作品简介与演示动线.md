## 一、作品简介

### 短版（约 150 字，投稿表用）

**新员工仿真培训系统**是一套面向连锁零售企业新员工入职培训的销售话术对练工具。学员在仿真的微信对话界面中应对 AI 扮演的刁难客户，每轮回复即时给出五维评分与考察点判定，训练结束后生成能力报告与进步对比；带教主管在侧看到本组短板并撰写辅导记录，学员端即时可见；运营部门负责场景内容治理与任务下发。系统为纯静态前端 + 零依赖 Node 服务端，双击即可运行，服务端离线时功能不中断。

### 长版（约 500 字，需要展开时用）

**要解决的问题。** 新员工入职培训里，销售话术是最难标准化的部分：集中授课只能讲"应该怎么说"，真实对练要占用带教主管大量时间，而新人第一次独立面对客户时往往是几个月后。结果是"听懂了但说不出口"——培训效果无法验证，带教成本却居高不下。

**我们的做法。** 把对练这件事做成可重复、可量化、可留痕的：学员在仿真的微信界面里和 AI 客户对话，客户会按预设剧本逐轮发难（压价、质疑品质、要求账期、投诉临期），学员打字或按住说话作答，系统对每一轮从五个维度打分，并明确告诉学员"这一轮考察的是什么、你哪句话没落在点上"。练完出报告：综合分、五维能力、逐句点评、与上一场同场景的对比、下一步该练什么。

**三端协同。** 学员练完之后，价值不该停在分数上：带教主管在工作台看到本组谁在掉队、为什么掉队，点开就能回看逐轮对话并写辅导记录——这条记录会出现在学员端的「带教留言」里。运营部门则负责场景内容的治理（只有审核通过的场景能下发、被修改后自动退回待审）与任务下发。

**技术特点。** 前端是纯静态页面，零 CDN、零构建、双击即开；服务端零 npm 依赖（Node 22 内置 SQLite），单文件部署。评分支持双通道：接入大模型时走模型评分，未接入或服务不可达时自动降级到内置关键词引擎与前端本地引擎，练习流程不中断。所有通道状态在界面上如实标注，不把模拟说成 AI。

**评分可靠性。** 评分接 DeepSeek `deepseek-flash`，金标 30 条实测相关性 pearson 0.871、平均分差 MAE 9.80 分（与人工标注分对比），可用内置脚本复现。未配置 Key 时自动降级为关键词引擎，界面上如实标注通道。语音输入为可选增强，不部署也能完整使用文字对练。

## 二、3 分钟演示动线

**演示前准备**（30 秒，不在计时内）

```bash
node server/index.js              # 启动服务端（零依赖）
# 浏览器开两个标签：
#   A: http://127.0.0.1:8848/仿真培训原型-微信风格.html?as=L01
#   B: http://127.0.0.1:8848/教练工作台-带教主管.html
# B 页登录 **zhoumin / coach123**（带教主管）
#    ⚠️ 别用 admin：辅导记录会署成「系统管理员」，不像真实主管写的。
```

> 演示库为出厂状态：3 个场景、12 名学员、5 个任务、28 条成绩。

---

### 0:00 – 0:25 ｜ 开场：说清痛点

**讲**：
> "新人培训最难的不是讲，是练。集中培训讲完，新人第一次独立面对客户可能是三个月后——中间没有任何安全的地方可以试错。我们做的就是那个安全的地方。"

**做**：停留在 A 页（学员端），不要点击。

---

### 0:25 – 1:15 ｜ 学员端：一次完整对练（核心）

**做**（按顺序点）：

1. 指左侧「本次训练任务」卡 —— "运营下发的任务，场景、达标线、截止时间都在这里，点这个按钮直接开练。"
2. 点 **`开始练习`** → 自动进入「王姐」会话
3. 输入一句**不理想**的回答，例如：`我们这个价格已经很实惠了，您可以先试试`
4. 发送 → 指出右侧变化："这一轮没命中考察点，系统直接告诉我这轮要的是'先确认用量再谈价格'，对应哪项能力、当前多少分。"
5. 再输入一句**命中**的回答：`想先了解下您门店日均客流和现在的配送频次，我好给个匹配的方案`
6. 发送 → "这次命中了，目标清单自动打勾。"
7. 点顶部 **结束/交卷** → 出报告

**讲**（对着报告）：
> "报告不只是分数：五维能力、逐句点评（哪句话该怎么做）、和上一次同场景的对比——这是学员最需要的，他能看到自己进步了没有。"

> ⏱ 若时间紧，第 3–6 步可只做一次发送，直接交卷。

---

### 1:15 – 2:00 ｜ 教练台：从数据到辅导（体现协同）

**做**（切到 B 页）：

1. 指顶部 KPI —— "达标率、平均分都是本组口径，脚注给了全体做对照；右边直接写'高于/低于全体几个百分点'，不是拍脑袋。"
2. 指「今日待办」—— "每条都写了为什么该催：逾期未提交、临近截止、连续低分，还写明是哪几个人。"
3. 点**任意一个高风险学员行** → 打开抽屉
4. 指抽屉里的**逐轮对话回看** —— "教练能看到学员每一句说了什么、AI 给了什么反馈，不用猜。"
5. 在「带教留言」框写一句：`价格异议这轮，先问用量再报价，别一上来给折扣` → 点保存

---

### 2:00 – 2:30 ｜ 回到学员端：闭环（这是最该强调的一分钟）

**做**（切回 A 页，刷新）：

1. 指右栏 **「带教留言」** —— "刚才教练写的那句话，现在出现在学员这里了。"
2. 指 **「我的成长」** —— "按入职天数推算的阶段、这阶段的重点能力和目标分，还有一句下一步该练什么。"

**讲**：
> "很多培训系统做到'出分'就结束了。但分数不会教人——人教人。所以我们把教练的辅导接进了学员端，这一条不做，前面所有的数据都白攒。"

---

### 2:30 – 2:55 ｜ 运营端：内容治理与规模化

**做**（切到运营后台 `管理后台-仿真培训.html`，admin 登录）：

1. 指数据看板 —— "每个 KPI 都带'本周 vs 上周'，避免孤立数字没法判断好坏。"
2. 点 **任务下发** → "四步向导：选场景 → 选人 → 设达标线与截止 → 下发。会记住上次的配置，例行下发不用重填。"
3. 点 **场景库** → 指审批状态列 —— "只有'已发布'的场景能下发；已发布的场景被修改会自动退回待审。内容是有人管的。"

---

### 2:55 – 3:00 ｜ 收尾

**讲**：
> "技术上它是纯静态前端加零依赖服务端，双击就能跑，断网也能练——这是为了让它真的能在门店里用起来，而不是又一个只能在会议室演示的系统。"

## 三、被问到时的应答要点

| 可能的问题 | 怎么答（别说满） |
|---|---|
| **"评分准吗？接的什么模型？"** | 接的是 DeepSeek `deepseek-flash`。金标 30 条实测：**pearson 0.871、MAE 9.80 分**（与人工标注分的相关性 / 平均分差）。这两个数用 `node server/tools/calibrate.js` 可复现。别说成"准确率 87%"——pearson 是相关性不是准确率。 |
| **"和市面上的 AI 陪练有什么区别？"** | 差别不在"能对话"，在**闭环**：评分 → 教练辅导 → 学员可见 → 进步对比。多数产品停在第一步。 |
| **"能支持多少人？"** | 演示库 12 人。架构上单进程 + SQLite，索引按万级记录设计，但**没做过万级压测**，如实说。 |
| **"语音怎么实现的？"** | 本机 FunASR（可选增强，约 900MB 模型）。**不装也能完整用文字对练**，评委复现不需要部署。 |
| **"数据安全怎么保证？"** | 数据可见范围三档（全部/本部门/本人带教），判断集中在 `core.js` 一处；登录鉴权 + 审计日志。但**没有 HTTPS**，正式对外要加反向代理。 |
| **"为什么不用 React/Vue？"** | 刻意选择：门店网络不稳定、IT 支持弱，双击能跑的静态页面最不容易坏；零依赖也意味着不会因为依赖升级而突然跑不起来。代价是工程化程度不如框架，我们用品控脚本（404 条前端断言 + 模块检查）来补。 |

## 四、演示避坑清单

- [ ] 演示前执行 `node server/tools/reset.js --yes` 恢复出厂数据（避免上次自测的残留出现在看板上）
- [ ] 确认服务端已启动（`curl http://127.0.0.1:8848/api/v1/status` 有返回）
- [ ] 两个标签页**提前登录**，别在台上输密码
- [ ] 学员端先关掉新手引导（点「我知道了」），避免遮挡
- [ ] 不要在现场演示「校准」和「场景编辑保存」——前者需要 API Key，后者会让场景退回待审导致后续下发失败
- [ ] 手机端如需展示，用真机访问同一局域网 IP，iOS Safari 效果最好
- [ ] **演练完一定要 reset**：现场练的每一场都会真实落库，看板会多出"今天"的数据
- [ ] 学员端右上角「…」可**提前结束练习**（连点两次），演示不必练满 6 轮
