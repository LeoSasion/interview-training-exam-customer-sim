## 二、P0：演示现场会被一眼看穿的（建议参赛前必改）

### 1. 同一套数据，三个"今天"

| 页面 | 时间基准 | 表现 |
|---|---|---|
| 学员端 | 冻结 `new Date(2026,9,5)`（`仿真培训原型-微信风格.html:833`） | 截止 10-10 的任务显示「剩 5 天」 |
| 教练台 | 冻结 `new Date('2026/10/05 20:00')`（`教练工作台-带教主管.html:403`） | 「待完成 2 人次 · 暂无逾期」 |
| 管理后台 | 真实 `Date.now()`（`管理后台-仿真培训.html:809`） | 同一任务「已逾期 19 天」 |

后果：今天是 10-29，管理端任务列表会写「已逾期 19 天」，学员端同一任务写着「剩 5 天」还能点「开始训练」。评委只要两页对照就发现。另外管理端 KPI 出现「本周 0 场 / 本周 0 人达标」，而头部又写 32 场累计——因为种子数据全在 10-05/10-06。

建议：统一为一个基准日（推荐真实今天），或全部改读 `TRAIN.meta.updatedAt` 做演示基准并在页面上写明「演示基准日：YYYY-MM-DD」。**三处一起改，别只改一处。**

### 2. 演示库被自测写了 4 条脏数据，直接把管理端数字算歪

```
库里 records = 32 条，其中 4 条 learner_id 为空、score=0（10-27 自测残留）：
R-S-20261027-LFMF / MHAX / 6EBX / H1CV
```

| 指标 | 学员端 / 教练台（本地 28 条） | 管理后台（服务端 32 条） |
|---|---|---|
| 累计练习 | 28 场 | 32 场 |
| 平均分 | 69 分 | 61 分 |
| 整体达标率 | 68% | 59% |

更尴尬的是管理端自己写着「全部指标均由共享数据源 data/app-data.js 实时计算」（`管理后台-仿真培训.html:280`），而实际数字来自 SQLite。自测本应清场，但 10-27 那 4 条漏了。

建议：参赛前 `node server/tools/reset.js --yes` 重播种子（种子 = 3 场景/12 学员/5 任务/28 成绩），并把这两处口径写死在文案上（要么都读服务端，要么都读本地）。

### 3. 教练台 KPI 口径混用 + 「低于整体水平」是写死的

- 同一行 KPI 里：`我的学员 12 人 / 28 场 / 69 分 / 68%` 来自本地，`全体均分 61` 来自服务端。两个口径并排，看着像"我的学员高于全体"，其实本地全体也是 69 分。
- 「达标率 68% · 低于整体水平」来自 `passRate >= 70 ? '高于整体水平' : '低于整体水平'`（`教练工作台-带教主管.html:863`）——阈值写死 70，根本没跟整体比。实际整体是 59%（服务端）/68%（本地），两个都说明这句判断是错的。

建议：改成与实际整体达标率比较（`passRate >= overallRate`），并统一数据源。
